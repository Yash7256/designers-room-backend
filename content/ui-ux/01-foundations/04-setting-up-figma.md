# Setting up Figma

*The 30-minute setup that saves you months of mess.*

## TL;DR

Figma is a workspace, not a magic design button. A good setup is boring: one place for each project, clear pages, named frames, and a habit of cleaning up as you go. Do this once and every file after it gets easier.

---

## Chapter 1: Decide what the file is for before you open it

The most common Figma mistake happens before you draw anything: you open a blank file without deciding what it is for.

A file can be:

- A place to explore ideas.
- A place to build wireframes.
- A place to design final screens.
- A place to document a design system.
- A place to hand off to engineers.

Those are different jobs. They need different levels of polish and different organisation.

### Start with a project, not a file

Figma projects are folders. Use them.

A simple structure:

```
Designer's Room
  UI/UX roadmap
    Practice files
    Portfolio
    Design system
```

One project per major area. One file per coherent piece of work. Do not make a new file for every screen unless the screens belong to different products.

### Name the file like a person will search for it later

Bad: `Untitled`, `Final`, `Final final`, `Screen 1`.

Good: `UI/UX – Onboarding flow`, `Practice – Dashboard teardown`, `Portfolio – Case study 01`.

The name is the first piece of organisation. It costs five seconds and saves ten minutes.

### A cover frame is not vanity

A cover frame tells you what the file is, who made it, and what state it is in.

Include:

- Project name.
- Your name.
- Date or version.
- A one-line description.
- A status: explore, in progress, ready for review, shipped.

It is the first thing you see when you open the file. Make it useful.

## Chapter 2: Use pages to separate stages of work

Pages are cheap. Use them.

A practical page structure for a beginner:

1. **Cover** – what this file is.
2. **Explore** – messy ideas, references, sketches.
3. **Wireframes** – structure and flow.
4. **Final** – polished screens.
5. **Components** – reusable pieces, if the file needs them.
6. **Archive** – old versions you are not ready to delete.

### Why separate explore and final

Exploration is supposed to be messy. Final work is supposed to be intentional.

If they live on the same page, you will either:
- Polish ideas too early, or
- Accidentally leave a rough sketch in the final file.

Separate pages give you permission to be messy in the right place.

### Keep the final page clean

The final page should contain only what someone needs to understand the design.

- Screens in order.
- Clear frame names.
- Notes where the flow is not obvious.
- No random rectangles, old versions, or experiments.

If you have to explain which frame is the real one, the page is not clean.

### Don't over-organise

You do not need a page for every tiny thing. A good rule: if you would scroll for more than a few seconds to find it, it probably needs its own page or a better name.

## Chapter 3: Frames, layers and naming

Frames are the containers that make Figma manageable. Layers are how you find things inside them.

### Use frames for screens, not random rectangles

A frame is a screen, a component, a card, or a defined area. A rectangle is a shape.

If it is a screen, make it a frame. If it is a button, make it a component. If it is a decoration, a rectangle is fine.

### Name layers while you still remember

A layer called `Rectangle 47` tells you nothing. A layer called `Card / header` tells you where you are.

You do not need perfect names. You need names that are true.

A simple convention:

- `Screen / Onboarding – step 1`
- `Section / Header`
- `Component / Button / Primary`
- `Icon / Arrow right`

Use slashes to create groups. It makes the layer panel easier to scan.

### Group when it helps, not by default

Grouping everything creates a maze. Group when the things belong together and you need to move or hide them as a unit.

A card's content? Group or frame. A random set of icons? Maybe just name them.

### Clean up at the end of a session

Five minutes of cleanup saves an hour later.

- Delete empty frames.
- Rename the layers you touched.
- Move experiments to the explore page.
- Check that the final page still makes sense.

This is not busywork. It is how you keep the file usable for future you.

## Chapter 4: Set up the habits that prevent mess

The setup is not just the first hour. It is the defaults you repeat.

### Use styles and variables early

Even a beginner file benefits from a few shared styles:

- Text styles for headings, body, labels, and captions.
- Colour styles for background, text, border, and accent.
- Spacing values you reuse.

You do not need a full design system. You need enough consistency that you are not choosing a new grey every time.

### Keep a scratch area

Every file needs a place for things that are not ready.

A `Scratch` page or a corner of the explore page is fine. Put half-ideas there instead of leaving them on the final page.

### Save versions before big changes

Figma keeps history, but named versions are easier to find.

Before a big restructure, save a version called `Before layout change`. If you hate the change, you can compare instead of guessing.

### Do not use the file as a to-do list

A file full of `TODO` frames becomes noise. Use comments or a separate notes page. Keep the canvas for design.

### Review the setup once a month

Open the file and ask:

- Can I find the final screens in under ten seconds?
- Are the names still true?
- Is there anything here I am afraid to delete?
- Would another designer understand this file without me?

If the answer to the last question is no, the setup needs work.

---

## Common mistakes

**Mistake 1: One giant page.** Everything ends up on one canvas. Finding anything becomes a scroll hunt.

**Mistake 2: No naming.** You will not remember what `Frame 132` was tomorrow. Neither will anyone else.

**Mistake 3: Polishing explore work.** Exploration should be fast and disposable. Polish belongs on the final page.

**Mistake 4: Building a design system before you have a design.** Start with a few styles. Add structure when repetition appears.

**Mistake 5: Treating organisation as a one-time task.** Files drift. A five-minute cleanup each session keeps them usable.

## Try it

Set up one project file:

1. Create a project called `Designer's Room`.
2. Create a file called `UI/UX – Practice`.
3. Add pages: Cover, Explore, Wireframes, Final.
4. Make a cover frame with the project name, your name, and today's date.
5. Add one frame called `Screen / Practice` on the Final page.

That is enough. You do not need a beautiful file yet. You need a file that will not fight you later.
